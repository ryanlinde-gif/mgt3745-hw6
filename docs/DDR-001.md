# DDR-001: bolt.new Build

## Task

Feature **F3, Share of Top Skills Held**, from the team `FEATURES.md`: three
EARS rows, F3-1, F3-2 and F3-3. The input was
[prompts/PROMPT.md](../prompts/PROMPT.md), pasted once, unchanged. No follow-up
prompt was sent.

## Tool and Model

bolt.new, 2026-10-20, Standard mode as shown in the interface.

## Economic Rationale

| | Hours |
|---|---|
| Build F3 by hand, at my HW4/HW5 pace | 2.0 |
| The delegation itself | 0.2 |
| Evaluating the output, extracting the arithmetic, stripping the credential | 1.1 |
| **Net** | **+0.7** |

Was it worth it? **For a shippable F3, no.** The delegation cost 1.3 hours and
saved 2.0, but what came back cannot be used: 20 files and 18 dependencies on a
stack ADR-001 did not choose. The three lines of arithmetic I kept would have
taken ten minutes to write.

**As evidence, yes, and that is what this assignment bought.** The question was
not "can bolt write this feature." It was "what does bolt do when my
specification is silent," and the answer is a Postgres database. That is worth
more to my team than the build.

## Trust Boundary

The F3 EARS rows, the Devon persona from `USERS.md`, and my `STYLE.md` colour
tokens crossed to bolt.new under its free-tier terms. No real student data, no
customer data, no credentials went out. **I am accountable for what crossed.**

**Reverse crossing, and it is the interesting direction here.** bolt sent back
more than code:

- **18 direct dependencies** (React, TypeScript, Vite, Tailwind, ESLint,
  PostCSS, `@supabase/supabase-js`, `lucide-react` among them), none requested.
- **A hosted Supabase Postgres database**, with a migration file and seeded
  rows, provisioned on bolt's side for a feature that is arithmetic over ten
  strings.
- **A `.env` file containing a live `VITE_SUPABASE_URL` and
  `VITE_SUPABASE_ANON_KEY`.** It was in the project root of the download.
- **`.bolt/prompt`**, a hidden instruction file I did not write, telling the
  model to make designs "beautiful, not cookie cutter" and "fully featured and
  worthy for production." That instruction competed with my specification and is
  the most likely reason a three-row feature arrived with a database.

## Retries and Changes

**Retries: none.** One prompt, one build.

**Changes, both recorded rather than silent:**

1. **I deleted `project/.env` before committing `builds/bolt.zip`.** It held a
   live Supabase URL and anon key, and this repository is public.
   `STANDARDS.md` rule 9 says no credentials in repositories, ever, and I am a
   code owner of that file. The anon key is a publishable key rather than a
   service key, so the exposure would have been small, but "small" is not the
   standard the rule sets. Everything else in the zip is as downloaded.
2. **I extracted the arithmetic from `src/components/SkillMatch.tsx` into
   `evals/impl/bolt.js`** so the shared test could call it directly. Lines 5
   and 65 to 75, copied unchanged. Only the React wrapper, `useMemo` and the
   props plumbing, was removed. No logic was altered; altering it would have
   made the comparison meaningless.

## Verification Performed

Compared against the three F3 EARS rows, row by row, in
[COMPARISON.md](../COMPARISON.md), each cell citing a file and line.

Then against the same four code-eval checks AI Studio faced, in
`evals/shared.test.js`. **bolt passed 4 of 4**, including the twelve-skill case
that AI Studio fails.

**What I could not verify.** Whether the Supabase project behind that `.env`
still exists, who can reach it, or what bolt stored in it. I did not connect to
it. The build's correctness was established from the extracted arithmetic, not
from a running database, so nothing in my result depends on that service.

**What I could not capture.** bolt's preview renders blank, so there is no
screenshot of the working build. The page depends on the Supabase project bolt
provisioned, and that project is not reachable from my session. The blank pane
is recorded in `docs/img/bolt.png` rather than omitted, and the row-by-row
evaluation was therefore done against the source in
`builds/bolt-src/project/src/components/SkillMatch.tsx` and against the
extracted arithmetic under test, not against a running page. That is a real
limit on the F3-2 presentation judgment: I judged bolt's amber alert from its
JSX and its styles, not from seeing it on screen.

**One row I marked Partial rather than Pass, and it is a judgment call.** F3-2
forbids telling the student whether to apply. bolt's text obeys. Its
presentation renders the below-half case in an amber alert box with a warning
triangle. I could not settle that with a test, so it went to a second grader in
[JUDGMENT.md](../JUDGMENT.md).
